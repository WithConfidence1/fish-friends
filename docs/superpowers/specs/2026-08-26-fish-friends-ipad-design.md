# Fish Friends: iPad App Design

Date: 2026-08-26
Status: Approved 2026-08-27. Built without audio (see plans/2026-08-27-fish-friends-ipad-no-audio.md); voice batch deferred to Taylor.

## What this is

Fish Friends (Tap and Count) is a cartoon aquarium math game for Taylor's 4-year-old daughter, built as a fully working HTML prototype and handed off in `~/Downloads/design_handoff_fish_friends`. This project ships it to her iPad as a native app with a warm human-sounding voice replacing the robot speech synthesis.

Decision (Approach C): wrap the working prototype in a native WKWebView shell now. A full SpriteKit rebuild only becomes a project later if the wrapper shows seams. The voice clips carry over unchanged either way.

## Goals

1. An app on her iPad home screen: full screen, offline, screen stays awake, installs for a year via Taylor's Apple Developer account.
2. All 108 spoken lines play as natural pre-recorded MP3s generated by AI, with the exact filenames the game already looks for. No robot fallback audible in normal play.
3. Taylor can later re-record any line himself by overwriting the MP3. Nothing else changes.

## Non-goals

- No SpriteKit rebuild (that is a separate future project with its own spec).
- No persistence guarantees. The game's localStorage keys (`tap-count-progress`, `tap-count-treasures`) behave however WKWebView defaults behave. If her tank resets between sessions, that is acceptable by design; the long-term treasure loop is intentionally shallow in v1.
- Nothing from the handoff README's "not yet built" list: chest anticipation, affectionate pets, her name in celebration lines, parent gate, new levels, celebration variety.
- No App Store or TestFlight distribution.

## Project layout

`~/Code/fish-friends` (git repo):

- `web/` — the real game. `index.html` (renamed from `Tap and Count.dc.html`), `assets/kit/` sprites, `assets/voice/` the 108 generated MP3s.
- `app/` — Xcode project `FishFriends`, SwiftUI shell.
- `tools/` — voice generation script and clip review page.
- `docs/` — this spec, plus the handoff `README.md` and `VOICE.md` copied in as reference.
- `reference/` — the original encoded bundle `Fish Friends - iPad.html`, untouched, for comparison.

## Component 1: the native shell (`app/`)

A SwiftUI app whose entire UI is one full-screen WKWebView loading `web/index.html` from the bundle via `loadFileURL`, with read access to the `web/` directory.

- iPad-only target, iPadOS 16+, all orientations (the game handles any aspect).
- Status bar hidden, safe areas ignored, black background behind the canvas.
- `isIdleTimerDisabled = true` while the app is active (wake lock).
- `mediaTypesRequiringUserActionForPlayback = []` and `allowsInlineMediaPlayback = true` so clips play on first tap.
- AVAudioSession category `.playback` so the aquarium is audible even with the mute switch on.
- Scroll, bounce, pinch zoom, link previews, and text-selection callouts disabled on the web view. No navigation is possible; the web view only ever shows the local game.
- App icon cut from the orange clownfish sprite on a water-blue background, generated at all required sizes.

What it depends on: the `web/` folder contents. Nothing in the game changes to run inside it.

## Component 2: the voice batch (`tools/`)

A script that produces all 108 clips and proves none are missing.

- Parses the `| Say this | Save as |` tables directly out of `VOICE.md`, including each section's italic tone direction.
- Provider: ElevenLabs (Taylor's API key required). Fallback provider if ElevenLabs is rejected at audition: OpenAI TTS.
- Step 1, audition: generate one sample line in 3 or 4 candidate voices. Taylor picks the voice before the full batch runs.
- Step 2, full batch: generate every line with the chosen voice, steering delivery per section tone direction. Post-process with ffmpeg: numbers one through ten trimmed tight with no lead-in silence; every other clip padded to roughly 0.2s of silence at start and end, per VOICE.md.
- Step 3, verification: cross-check three sources against each other: VOICE.md filenames, the slugs the game's script actually generates, and the files present in `web/assets/voice/`. Any mismatch is a build failure, because a mismatch means silent robot-voice fallback.
- Step 4, review: a single local HTML page listing all 108 clips with play buttons and the line text, so Taylor can audition everything in a couple of minutes and flag rejects for regeneration.

## Verification

In the iPad Simulator before any install: game loads full screen, tap counting works, a sampled set of voice clips plays as MP3 (confirmed by absence of speechSynthesis calls at runtime), celebration and reward flow completes, app relaunch works. Then Taylor installs to her iPad from Xcode with his developer account and optionally locks it down with Guided Access.

## Risks

- ElevenLabs delivery may need per-section prompt tuning to hit "warm, unhurried, small smile." The audition step and review page exist to catch this cheaply.
- The prototype was tuned in Safari; WKWebView is the same engine, so behavior differences are unlikely. The simulator pass is the check.
